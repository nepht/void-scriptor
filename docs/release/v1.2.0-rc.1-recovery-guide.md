# Void Scriptor v1.2.0-rc.1 — Recovery Guide

Status: panduan lokal untuk kandidat RC; gunakan salinan/backup dan jangan menguji kegagalan pada project pengguna.

## Sebelum migrasi atau repair

1. Tutup sesi penulisan lain untuk project yang sama.
2. Buat backup dan verifikasi bahwa paket backup dapat dibaca.
3. Pertahankan package sumber; migrasi/repair tidak boleh menimpa satu-satunya salinan.
4. Catat lokasi project dan pesan error tanpa memasukkan kredensial atau isi privat ke laporan.

## Project gagal dibuka

1. Jangan menghapus `session.lock`, database, journal, atau folder quarantine secara manual.
2. Jalankan diagnostics/integrity scan dari alur recovery aplikasi.
3. Tinjau repair preview. Repair harus membuat backup sebelum mutasi.
4. Gunakan reindex hanya untuk index yang tidak sinkron; reindex bukan pengganti pemulihan data sumber.
5. Bila schema lebih baru daripada aplikasi, hentikan. Buka dengan versi aplikasi yang mendukung schema tersebut; jangan downgrade database in-place.

## Draft atau sesi terinterupsi

- Biarkan startup recovery membaca journal/marker dan menawarkan pemulihan.
- Pulihkan draft melalui alur aplikasi, lalu verifikasi isi sebelum melanjutkan edit.
- Marker owner yang ambigu harus fail-closed; jangan merebut lock hanya berdasarkan umur file.

## Import/export terinterupsi

- Import menggunakan staging/claim dan rollback dua fase. Jalankan ulang recovery, bukan memindahkan folder staging secara manual.
- Export menulis artefak sementara sebelum verifikasi/rename. Artefak `.tmp` bukan hasil final dan boleh direklamasi oleh percobaan ekspor berikutnya.

## Corruption dan file media hilang

- Integrity scan membedakan schema, orphan link/asset, media hilang, dan index tidak sinkron.
- File orphan dikarantina; jangan hapus quarantine sebelum hasil repair diverifikasi.
- Media hilang tidak boleh diganti diam-diam. Pulihkan dari backup/sumber asli atau pertahankan missing-file state.
- Simpan recovery log untuk handoff support.

## Batas bukti

Crash, disk-full, permission-loss, corrupt-index, interrupted migration, dan simulasi power-loss telah memiliki bukti test lokal. True hardware power loss, USB cold-eject, dan dialog crash native belum tersertifikasi untuk kandidat ini.
