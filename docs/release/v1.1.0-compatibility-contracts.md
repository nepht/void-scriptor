# v1.1.0 Compatibility & Operations Contracts (stable)

Deklarasi kanonik untuk rilis stabil. Sumber: ledger sprint 105 + kode
terkunci @696a667. Perubahan pasca-rilis = sprint 107.

## Kontrak kompatibilitas

| # | Kontrak | Deklarasi |
|---|---|---|
| C1 | Project format | major **1**, format schema **16**; project v1.0.x didukung penuh; versi masa depan yang tak dikenal DITOLAK dengan aman (validator menolak, tidak menebak) |
| C2 | Database schema | **v56** tercatat; migration manifest 53→54→55→56 semuanya createTable ter-guard; rollback = restore backup pra-migrasi byte-for-byte (105.11); batasan: downgrade in-place v56→v53 TIDAK disediakan |
| C3 | Plugin API | major **1** dibekukan; `evaluatePluginStep` menolak major ≠1 via `rejectedApiVersion` (terlihat, tanpa fallback senyap); deprecation: tidak ada API yang dideprekasi pada major ini |
| C4 | Workflow/automation schemas | generasi **1** untuk workflow_definition, workflow_execution, automation_rule, trigger, template_package (`ReleaseSchemas`) |
| C5 | Supported platforms | Linux x64 (WSL) tervalidasi; Windows/macOS/Web/Mobile belum dieksekusi siklus ini (KI-03) |

## Upgrade path (106.24)

- Sumber didukung: fresh install, `1.0.x` (schema DB ≤53) → auto-migrate ke
  v56 saat buka project, beta/RC → identik schema (no-op).
- Data: backup pra-migrasi otomatis sebelum upgrade; rollback = restore file.

## Rollback readiness (106.25)

- Rollback artefak: artefak rc-1/beta tetap tersedia di repo (manifest
  masing-masing) — promosi metadata tidak menghapus apa pun.
- Rollback data: restore backup pra-migrasi (teruji byte-for-byte).
- Runbook: `docs/release/v1.1.0-known-issues.md` + baris 105.10–105.11.
- Batasan kompatibilitas data: project yang sudah termigrasi ke v56 tidak
  bisa dibuka oleh build v1.0.x lama.

## Staged rollout plan (106.15–106.16)

| Tahap | Audiens | Window observasi | Kriteria lanjut |
|---|---|---|---|
| 1 — kanal lokal | dev machine Choirudin | ≥24 jam pemakaian nyata | tanpa crash/migrasi gagal |
| 2 — terbatas | undangan manual | ≥72 jam | crash-free ≥99%, migrasi gagal =0 |
| 3 — umum | publik | kontinu | stop conditions di bawah |

Stop conditions (satu saja = hentikan tahap): insiden P0; regresi integritas
data; kegagalan migrasi >0.5% sesi upgrade; crash rate >1%; kegagalan update
>2%; insiden keamanan.

## Monitoring & operasional (106.26–106.30)

- Sinyal dipantau: crash_rate, startup_failure, migration_failure,
  update_failure, workflow_failure, automation_failure,
  performance_regression — saat ini SEMUA dari observabilitas build lokal;
  telemetry produksi BELUM ada (jujur: pengumpulan sinyal publik menunggu
  infrastruktur, konsisten KI-03/KI-04).
- Crash workflow: signature grouping + redaction identifier-only + build
  identity wajib dilampirkan; intake via repo issues.
- Security intake: security@kontak repo / GitHub Security Advisory; triage
  owner: Choirudin; jalur patch darurat: branch hotfix v1.1.1 (prioritas P0/
  P1/security/data_integrity/update_failure).
- Privacy incident lifecycle: DETECTED → CONTAINED → INVESTIGATED →
  REMEDIATED → CLOSED (dokumen proses, belum pernah dieksekusi karena
  belum ada insiden).
